01 — The business case

An agent with tools is an insider
you didn't hire.

LLM agents read mail, run code and call APIs. Every capability is also an attack surface, and prompts are now an input channel for adversaries. The question is no longer whether to deploy agents, but what they are allowed to touch when they are manipulated.

RISK 01

Prompt injection

Hostile instructions hidden in documents, web pages or tickets quietly redirect the agent's intent.

RISK 02

Silent data exfiltration

A tool call, a rendered link, a DNS lookup: secrets leave through channels no one thought to watch.

RISK 03

Excessive agency

Shell, filesystem and network access granted "for convenience" turn one bad decision into a breach.

03 — Lab 1 · Under the hood

LangChain builds the parts.
LangGraph decides the flow.

LangChain gives you a model, tools and messages. LangGraph assembles them into an explicit state machine: nodes do the work, edges decide what happens next, and a shared state travels along. Control flow becomes something you can read, test and audit.

LangChain PARTS

Chat model, @tool functions, messages, prompts. Swap a local Ollama model for an API model without touching the rest.

LangGraph FLOW

StateGraph, conditional edges, checkpoints and interrupt() for human approval. This is where the policy gate lives.

OpenShell WALLS

Where tools actually execute: isolated runtime, declarative policy, nothing reachable that wasn't granted.
